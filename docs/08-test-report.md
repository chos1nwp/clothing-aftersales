> 被测系统：服装网店退换货处理系统（Spring Boot 3.2.5 + MyBatis 3.0.3 + MySQL 8.0.46 + 原生 JS 前端）
> 测试时间：2026-09-30 　测试环境：Windows 10 26100 / JDK 17.0.20 / Maven 3.9.16 / Node v24.18.0（脚本断言用）/ MySQL 8.0.46（utf8mb4）
> 测试执行者：本项目开发者 + AI 助手（用例设计、脚本编写、结果判定见第五章协作记录）

## 1. 测试目标与判定标准

覆盖课程要求的五类场景：**正常、异常、边界、并发、越权**，并额外加一组**数据对账**和一组**错误处理**。

判定标准不是「接口返回 200」，而是三方同时对上：

1. 接口返回的业务码（`code`）与提示语（`message`）符合预期；
2. 页面会读到的字段（`status`、`statusLabel`、`afterSaleableQuantity`、`warehouseRecord` 等）符合预期；
3. 数据库里的行（`aftersales_order.status / refund_amount / closed_at`、`warehouse_record`、`aftersales_action_log` 的动作序列与可见性标记）符合预期。

## 5. 关键证据摘录

### 5.1 正常链路（组 A，节选脚本输出）

```
── 组 A 正常链路：退货申请 → 审核 → 寄回 → 收货 → 验货 → 确认退款
  PASS  A8 仓库登记收到包裹
  PASS  A9 收货不改变售后状态（收货只是业务事实之一）
  PASS  A10 数据库里有收货时间
  PASS  A12 验货后进入待确认
  PASS  A13 消费者调用客服接口被拒
  PASS  A16 退款金额由服务端按单价×数量算出（针织开衫 ¥189 × 1）
  PASS  A18 时间线动作顺序与链路一致
```

### 5.2 并发与越权（组 E，节选）

```
  PASS  E1 两名客服同时同意退回，只有一份写入成功（0+409）
  PASS  E2 同意退回的动作只记录一次
  PASS  E3 并发后状态只前进了一步
  PASS  E4 失败的一方拿到可理解的冲突提示
  PASS  E5 张三读取小林的售后单被拒
  PASS  E7 张三的售后列表里查不到这张单
```

### 5.3 演示脚本里的规则拦截语（`flow-demo.sh` 真实返回）

```
  3a 同一商品重复申请          → [409] 该商品已有正在处理中的售后申请，请先处理完再提交
  3b 额度已被历史售后单占用    → [400] 申请数量超出可售后数量，该商品当前最多可申请 0 件
  3c 申请他人订单商品          → [403] 只能对本人订单申请售后
  3d 超过售后期限              → [400] 已超过售后期限（签收后 7 天内可申请）
  8  消费者尚未寄回先收货      → [409] 客服尚未同意退回或消费者尚未确认寄回，仓库不能提前登记收货
  11 验货异常不写现象          → [400] 验货异常必须写清具体现象
  12 拒绝不写理由              → [400] 拒绝时必须填写理由
  15 张三访问小林的单          → [403] 售后单不存在或你无权查看
  16 已关闭的单再收货          → [409] 该售后单已关闭（已拒绝），不能再登记收货
```

### 5.4 换货链路的两条结论校验（`happy-path-demo.sh`）

```
  换货却填退款结论 → [400] 该售后单是换货，不能按退货处理
  换货补发但不给单号 → [400] 换货必须填写模拟补发单号
  换货补发 → ok，客服看到：已完成 补发单号=SF5566778899 退款金额=null
```

## 8. 未覆盖范围与已知限制

| 项 | 说明 | 处理方式 |
| --- | --- | --- |
| 并发窗口有限 | E1 用两个客服账号背靠背发请求，能否真正撞上进程调度取决于机器；断言只要求「一 0 一 409」，这个结论对串行与真并发都成立 | 若需要更强保证，可加 `version` 字段与压测工具，超出课程范围 |
| 图片凭证只测上传成功与归属校验 | 未测伪装扩展名、超大文件并发的磁盘行为（大小限制已有 400 提示） | 登记为已知限制 |
| 无自动化 UI 端到端测试 | 浏览器部分为人工点击 + 计算样式取证，未引入 Selenium/Playwright | 课程不要求，README 说明人工演示步骤 |
| 无单元/集成测试框架（JUnit） | 测试以端到端脚本 + 数据库断言为主，符合「小型系统链路可复现」的目标 | 第九章交付说明中登记为后续改进 |
| 性能与安全测试 | 未做压力测试；鉴权为 Session + 注解的演示级实现，无 CSRF Token、无密码策略 | 写入「已知限制」，不做隐瞒 |
